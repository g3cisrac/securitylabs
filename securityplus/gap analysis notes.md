Where you are compared to where you want to be. Emails. data gathering, team research. 
A gap analysis table is a structured comparison tool used to identify the difference between where you currently are and where you need to be — commonly used in cybersecurity for compliance, risk, and control assessments.
Purpose

    Identifies gaps between current security posture and a target standard (framework, policy, or requirement)
    Helps prioritize remediation efforts based on risk and effort
    Commonly used before audits, certifications (ISO 27001, NIST, PCI-DSS), or security program buildouts

Typical Table Structure
Column	Purpose
Requirement/Control	The standard or policy item being evaluated (e.g., "MFA required on all admin accounts")
Current State	What's actually in place today
Desired State	What the requirement/framework mandates
Gap	The specific difference between current and desired
Risk Level	Impact if the gap isn't addressed (Low/Medium/High/Critical)
Remediation Action	What needs to be done to close the gap
Owner	Who is responsible for fixing it
Target Date	Deadline for closing the gap
Example Row
Control	Current State	Desired State	Gap	Risk	Action	Owner	Date
MFA on admin accounts	Enabled for 60% of admins	100% required	40% of admins lack MFA	High	Enforce MFA via conditional access policy	IT Security	30 days
Why It's Used in Cybersecurity

    Compliance prep: shows auditors exactly what's missing before a formal audit
    Risk prioritization: not all gaps are equal — this table helps rank what to fix first
    Budget justification: quantifies gaps to justify security spending
    Progress tracking: re-running the analysis over time shows improvement

Key idea: it's essentially a "current vs. required" checklist that turns abstract compliance requirements into concrete, actionable, and trackable tasks.
